01 / WHAT CHANGED

The workflow, before and after.

BEFORE

Many people, many email threads.

SupplierEngineerReviewer
  1. 1Submit drawings by email
  2. 2Manually inspect files and lists
  3. 3Request corrections and resend

Versions, missing information and review status were spread across messages and manual checks.

AFTER

One submission, a connected workflow.

SubmitSystemReview
  1. 1Centralised submission and versions
  2. 2Extract data and validate rules
  3. 3Review exceptions and register assets

A FastAPI/Vue.js workspace makes tracking, validation results and error management visible in one place.

02 / TECHNOLOGY IN THE WORKFLOW

Follow the information through the system.

Select a stage to see its purpose, implementation technologies and operational safeguards.

Receive & version

AWS S3 + EventBridge

Store submitted drawings and route file-arrival events into the processing workflow.

Keep file identity and version context attached to processing status.

Buffer & process

SQS + Lambda

Decouple file arrival from processing so extraction work can be handled through an event-driven pipeline.

Track failed work separately so a retry does not obscure the original submission.

Extract drawing data

APS APIs

Use drawing APIs to turn document and object information into data the platform can validate and integrate.

Retain source references and separate extraction errors from business-rule violations.

Validate & structure

Python + FastAPI + SQL

Apply completeness, identifier and consistency checks, then persist structured results and workflow state.

Make duplicate, missing and inconsistent values actionable rather than silently accepting them.

Review & resolve

Vue.js + REST APIs

Provide document tracking, validation results and error-management interfaces for engineering users.

Keep per-document progress and error context visible during correction and resubmission.

Register & integrate

Master data + ETL/EAI

Connect validated engineering information to master data and downstream systems.

Keep integration status distinct from validation status for operational follow-up.

ENGINEERING JUDGMENT

The key boundary is between receiving a file, validating its information and registering it downstream. Separate states make partial failure visible and recoverable.

EXCEPTION & VALIDATION FOCUS

Duplicate submission · extraction timeout · invalid identifiers · failed downstream registration · release health checks

04 / OPERATIONAL RESULT

What changed in practice.

Replaced email-based handling with centralised submission, version control and automated validation. The platform handles approximately 30,000–70,000 drawings and automates registration of approximately 10,000 assets and components per FAB.
