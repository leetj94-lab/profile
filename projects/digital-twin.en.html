04 / ENGINEERING DECISIONS

DESIGN EXAMPLE

The selected asset must own the information on screen.

A hypothetical design exercise, separate from the real project contribution above. No employer architecture or measured outcomes are represented.

TECHNICAL CHALLENGE

An operator selects equipment A, then B. If A’s slower API response arrives last, the interface can show the wrong operating context beside B’s 3D selection.

DESIGN CHOICE

Make the decision explicit.

Scope requests to the selected asset. Cancel obsolete requests and reject stale responses; load operating, maintenance, and drawing panels independently.

Tradeoff Independent panels require more explicit UI states, but one unavailable service no longer blocks the whole equipment view.

EXCEPTIONS & RECOVERY

Keep failure recoverable.

Keep model navigation available when an API fails. Show per-panel availability and last-updated context, and make retry available without clearing the selection.

HOW I WOULD VERIFY THE DESIGN

Select A then B with reversed response times, and fail one information source. Expect only B’s context, working navigation, and the unaffected panels still available.
