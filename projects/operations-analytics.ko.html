01 / 무엇이 달라졌나

업무 흐름의 개선 전후.

개선 전

데이터는 있지만 운영 맥락은 분산.

  1. 1작업·소스를 개별 확인
  2. 2일관되지 않은 메타데이터 해석
  3. 3품질·장애 원인 수동 확인

파이프라인 상태, 데이터셋의 의미, 품질 신호를 운영 관점에서 연결할 필요가 있었습니다.

개선 후

데이터 기준과 파이프라인 상태를 함께.

  1. 1메타데이터·보안 분류 정의
  2. 2웹 애플리케이션으로 ETL 모니터링
  3. 3운영·품질 대시보드 활용

Oracle 작업 데이터, FastAPI 서비스, Vue.js 화면과 Spotfire 분석으로 파이프라인 운영을 지원했습니다.

02 / 업무 흐름 속 기술

정보가 시스템을 통과하는 과정.

단계를 선택하면 목적, 구현 기술, 운영상 보호 장치를 확인할 수 있습니다.

데이터셋 맥락 정의

Metadata + security classification

8개 인프라 시스템 데이터셋의 메타데이터와 보안 분류를 정의합니다.

후속 사용자가 데이터 관리 주체와 활용 제약을 이해하도록 합니다.

작업 상태 제공

Oracle + FastAPI

ETL 작업 정보를 운영 모니터링용 백엔드 서비스로 제공합니다.

소스 조회 불가, 정상적인 빈 결과, 작업 실패를 구분합니다.

모니터링·원인 확인

Vue.js + Spotfire

파이프라인 후속 조치를 위한 웹 모니터링과 운영·데이터 품질 대시보드를 제공합니다.

데이터 누락을 정상 결과처럼 표시하지 않고 갱신 시점과 오류 맥락을 제공합니다.

03 / 직접 개발한 영역

설계하고 개발하고 운영한 영역.

데이터셋 관리 기준

ETL 모니터링 개발

파이프라인 운영을 지원하는 FastAPI·Oracle·Vue.js 모니터링 애플리케이션을 개발했습니다.

운영 분석

운영·데이터 품질을 파악할 수 있는 Spotfire 대시보드를 구축했습니다.

설계의 핵심 판단

애플리케이션 가용성과 데이터 최신성은 서로 다른 신호입니다. 작업 실패, 정상적인 빈 결과, 소스 조회 불가를 사용자가 구분하도록 해야 합니다.
