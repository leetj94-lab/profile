01 / 무엇이 달라졌나

업무 흐름의 개선 전후.

개선 전

질문 하나에 여러 번의 수동 검색.

  1. 1관련 스키마·필드 확인
  2. 2쿼리 작성·자료 조회
  3. 3과거 일탈·조치 사례 검색

엔지니어링 조사에는 구조화된 데이터와 과거 품질 사례의 맥락이 함께 필요합니다.

개선 후

맥락을 담아 질문하고 근거를 검토.

  1. 1스키마 맥락으로 질문 해석
  2. 2SQL·API 데이터·유사 사례 조회
  3. 3엔지니어 판단으로 제안 검토

통계적 유사도와 LLM 제안을 결합해 데이터 값 검토와 조사를 지원하는 프로토타입을 구성했습니다.

02 / 업무 흐름 속 기술

정보가 시스템을 통과하는 과정.

단계를 선택하면 목적, 구현 기술, 운영상 보호 장치를 확인할 수 있습니다.

질문 이해

Schema context + user intent

엔지니어링 질문을 관련 스키마와 조회 맥락에 연결합니다.

데이터를 조회하기 전에 질의 범위를 제한합니다.

근거 조회

SQL + APIs + databases

구조화된 정보와 근본 원인·시정·예방 조치를 포함한 유사 품질 일탈 사례를 조회합니다.

응답을 확인하는 데 필요한 원천 맥락을 보존합니다.

검토 지원

Statistical similarity + LLM

유사도 신호와 언어 모델 제안을 결합해 엔지니어링 검토를 지원합니다.

제안은 엔지니어 검토를 거치도록 하고 근거 부족을 드러냅니다.

03 / 직접 개발한 영역

설계하고 개발하고 운영한 영역.

Amazon Bedrock AgentCorePythonSQLREST APIsStatistical similarity

에이전트 프로토타입 개발

스키마 기반 자연어 SQL 및 API·DB 조회를 위한 Amazon Bedrock AgentCore 어시스턴트를 독립적으로 프로토타이핑했습니다.

품질 사례 검색

엔지니어링 조사를 위해 유사 일탈, 근본 원인, 시정·예방 조치를 조회하는 기능을 개발했습니다.

데이터 검토·처리 경계

통계적 유사도와 LLM 제안을 결합하되 조회 맥락과 엔지니어의 검토를 흐름의 중심에 뒀습니다.

설계의 핵심 판단

엔지니어링 어시스턴트에는 자연스러운 답변 이상의 요소가 필요합니다. 스키마 맥락, 조회 가능한 근거, 데이터와 제안의 구분이 있어야 결과를 검토할 수 있습니다.
