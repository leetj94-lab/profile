04 / 기술적 판단과 문제 해결

가상 설계 사례

선택한 설비와 화면의 정보가 항상 일치하도록.

위의 실제 담당 역할과 구분되는 가상 설계 사례입니다. 재직 회사의 실제 아키텍처나 측정 성과를 나타내지 않습니다.

기술적 난점

사용자가 설비 A를 선택한 뒤 B로 이동했는데 A의 API 응답이 늦게 도착하면, B의 3D 선택 화면에 A의 운영 정보가 표시될 수 있습니다.

설계 선택과 이유

선택한 방식과 이유.

선택 설비별로 요청을 관리합니다. 이전 요청을 취소하고 늦게 도착한 응답을 무시하며, 운영·정비·도면 패널은 독립적으로 불러옵니다.

트레이드오프 패널별 상태 관리가 필요하지만, 하나의 서비스 장애가 설비 화면 전체를 막지 않게 됩니다.

예외 조건과 복구

실패해도 복구할 수 있도록.

API가 실패해도 3D 탐색은 유지합니다. 패널별 가용 상태와 갱신 시점을 표시하고, 설비 선택을 유지한 채 재시도할 수 있도록 합니다.

설계 검증 시나리오

A 선택 후 B로 바꾼 상태에서 응답 순서를 뒤집고, 정보 소스 하나를 중단합니다. B의 정보만 보여야 하며 탐색과 나머지 패널은 유지돼야 합니다.
