02 / AI 활용 철학

AI가 바꾼 개발 방식.
품질을 결정하는 전문성.

AI로 시스템 개발의 패러다임이 바뀌었다고 생각합니다. 누구나 코드를 생성할 수 있는 환경에서도 결과의 품질은 도메인 이해, 엔지니어링 경험, 적용하는 기준에 따라 달라집니다.

AI를 활용해 엔지니어링 판단을 팀이 반복 적용할 수 있는 방식으로 만듭니다. 문제를 정의하고, 표준을 정하고, 그 기준 안에서 코드를 생성한 뒤 검토하고 검증합니다.

01

생성 전에 업무 맥락부터

현업과 개발 경험을 바탕으로 사용자의 문제, 시스템 경계, 기대 동작을 먼저 정리한 뒤 AI에 구현을 요청합니다.

02

팀이 공유하는 개발 표준

코딩 패턴, 명명 규칙, API 계약, UI 기준, 오류 처리 규칙을 SKILL.md에 정리합니다. 팀 내 다른 사람이 AI를 사용해도 유사한 패턴과 동일한 표준을 따르도록 합니다.

03

공유·유지보수·재사용 가능한 코드

명확한 인터페이스, 모듈별 책임, 재사용 가능한 패턴을 정해 생성 코드가 공통 코드베이스에 어울리고 협업과 요구사항 변경에도 대응하도록 합니다.

04

미리 정의하는 기능·테스트 기준

코드 생성 전에 기능 수용 기준과 경계 조건·예외·복구 테스트 시나리오를 정의합니다. 생성된 코드가 이후에도 동작을 확인하고 테스트할 수 있는 구조를 갖추도록 합니다.

SKILL.md

공통 개발 기준을 재사용하는 지침.

스킬 레시피는 팀의 규칙을 명시하는 장치입니다. UI 디자인·코드 구조·테스트 생성이 작업자와 AI 활용 작업 전반에서 사전 정의한 기준을 따르도록 합니다.

ui-design/SKILL.mdcoding-standards/SKILL.mdtest-generation/SKILL.md
  1. 업무 이해
  2. 기준 정의
  3. 코드 생성
  4. 결과 검토
  5. 동작 검증

AI를 통해 개인의 작업 편의뿐 아니라 팀의 일관성, 신뢰성, 유지보수성, 개발 품질을 높이는 것이 목표입니다. 엔지니어링 판단과 생성 결과의 검토는 제가 책임집니다. 이 포트폴리오의 디자인·개발에도 AI를 활용했습니다.

01 / 무엇이 달라졌나

업무 흐름의 개선 전후.

개선 전

질문 하나에 여러 번의 수동 검색.

  1. 1관련 스키마·필드 확인
  2. 2쿼리 작성·자료 조회
  3. 3과거 일탈·조치 사례 검색

엔지니어링 조사에는 구조화된 데이터와 과거 품질 사례의 맥락이 함께 필요합니다.

개선 후

맥락을 담아 질문하고 근거를 검토.

  1. 1스키마 맥락으로 질문 해석
  2. 2SQL·API 데이터·유사 사례 조회
  3. 3엔지니어 판단으로 제안 검토

통계적 유사도와 LLM 제안을 결합해 데이터 값 검토와 조사를 지원하는 프로토타입을 구성했습니다.

02 / 업무 흐름 속 기술

정보가 시스템을 통과하는 과정.

질문 이해

Schema context + user intent

엔지니어링 질문을 관련 스키마와 조회 맥락에 연결합니다.

데이터를 조회하기 전에 질의 범위를 제한합니다.

근거 조회

SQL + APIs + databases

구조화된 정보와 근본 원인·시정·예방 조치를 포함한 유사 품질 일탈 사례를 조회합니다.

응답을 확인하는 데 필요한 원천 맥락을 보존합니다.

검토 지원

Statistical similarity + LLM

유사도 신호와 언어 모델 제안을 결합해 엔지니어링 검토를 지원합니다.
